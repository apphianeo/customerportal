What changes, and why

Seven moves, each one aimed at the same thing: get the reader to the code or the button faster, and make a forged copy of this email harder to pass off.

The hero photo is gone

In the current email the stock photo is the largest element and carries no information. On a phone it pushes the code below the fold. The logo alone now carries the branding. Most corporate clients block images by default, so the photo-led version currently arrives as a grey box; this one degrades to the brand name and stays fully readable.

The code is an object, not a sentence

Your OTP: 946683 inside a paragraph doesn’t scan. The code now sits in a plate that reuses the portal’s OTP input treatment, at 34px with wide tracking, with its expiry inside the same plate. One thing to read, not two.

One expiry, stated correctly

The spec table says 3 minutes; the current email says 5. Templates use 3 throughout. Drive it from one backend value so copy and token can’t drift apart again.

The yellow highlighter is gone

Highlighting on “OTP” reads as an unfinished Word document. Emphasis comes from type scale and the plate, which is what the portal already does.

Copy cut by roughly half

Before: “To ensure secure access to your UOIConnect account, we’ve generated a One-Time Password (OTP) for you. Please enter this OTP on the portal login page to proceed.” After: “Enter this code to finish signing in to UOI Customer Portal.”

The footer is legal text only

The blue copyright bar and the link row are gone. What remains is the required legal block, which sits below the card at 11px, the smallest type in the email, so it reads as document chrome rather than message content. The support route moved inside the card as closing fine print at 13px.

Every email says what to do if it wasn’t you

Login: change your password. Reset: ignore it, nothing happens. Change login ID: call us now, don’t enter the code. The highest-value copy in a security email, and the current template has none of it.

Nothing here is a new visual language

Every value is lifted from src/index.css and src/pages/auth/AuthUI.tsx. Two deviations are forced by the medium: rgba() borders are resolved to flat hex, because Outlook on Windows drops the alpha channel and renders them black; and shadows are dropped, because --shadow-card is invisible in most clients and the hairline border carries the same separation.

Before these go out

  • Host the logo and rebuild. The logo is inlined as a data URI by default so these files render on their own. Gmail and Outlook strip data-URI images, so before sending, host assets/uoi-logo.png and rebuild with EMAIL_LOGO_URL=https://… python3 emails/build.py. Alt text is UOI, so a blocked image degrades to the brand name.
  • Wire the merge fields. Currently Handlebars-style. Swap the delimiters for whatever your ESP uses.
  • Send a plain-text alternative. Transactional mail without a text/plain part takes a spam-score hit.
  • Check SPF, DKIM and DMARC. No amount of design makes an unauthenticated OTP email trustworthy.
  • Decide on the code in the subject line. Google, Stripe and Apple all do it, so the code is readable from the lock screen without opening the mail. The tradeoff is shoulder-surfing. Templates 1, 3 and 4 currently do it.
  • Confirm the reset-link TTL. Template 2 says 30 minutes.
  • Send me row 5. The “Others” section was cut off in the screenshot. Those scenarios slot into the same shell.
